# Skill: sec

Секреты в XChaCha20-Poly1305-файле, мастер-ключ — в системном хранилище ОС.
Отдельный CLI, ставится брю: `brew install kaidstor/tap/sec`. Исходники —
github.com/kaidstor/sec (это **не** rebrandy-проект: задачи в FB не заводить).

**Список команд — `sec --help`, флаги конкретной команды — `sec <cmd> --help`.**
Здесь только то, чего в `--help` нет: политика для агента и гочи.

## Адресация

Секрет = `<proj>/<KEY>`. Без проекта берётся имя текущей директории, поэтому
внутри папки сервиса достаточно `sec run -- just dev`.

Третья ось — инстансы (`-e commercial`): один сервис, несколько наборов значений
(стенды, компании). Конвенция: **сервис = проект, инстанс через `-e`**, набор
инстансов и дефолт объявляются в файле `.sec` в папке сервиса — его читают и CLI,
и агент. Там же список обязательных ключей для `sec check`.

## Политика для агента

1. **Значения секретов в чат не выводить.** `get` без `--clip`/`--peek`/
   `--fingerprint` — только по явной просьбе показать значение.
2. **Заведение — так, чтобы значение не прошло через чат и argv.** Пользователь
   копирует в буфер → `sec set <proj>/<KEY> --clipboard --clear`; либо он сам
   вводит скрытым вводом; либо значение генерируется (`sec gen`) и агент его не
   видит. Значение с диска — пайпом, не аргументом.
3. **Перед заведением — `sec find <KEY>`.** Такой ключ может уже лежать в другой
   пачке: тогда `sec link` (живая ссылка), а не копия. Общий источник правды не
   расходится, копии расходятся.
4. **Искать фильтром, а не глазами.** `sec find <шаблон>` по всему хранилищу,
   `sec ls <proj> --filter <шаблон>` внутри пачки. Не выгребать `sec ls --json`
   целиком, чтобы искать в выводе.
5. **Перед коммитом — `sec scan --staged`.** Перед показом лога или вывода
   команды, где мог засветиться секрет, — `<cmd> 2>&1 | sec redact`.
6. **Реорганизация — `sec mv`/`sec link`, а не `get`+`set`:** не раскрывает
   значение и сохраняет историю. Перед `rm ... --all` — подтверждение.
7. Если пользователь прислал значение открытым текстом в чат — сохранить можно,
   но предупредить, что оно засвечено, и предложить ротацию.

## Гочи

- **`run`/`export` не инжектят ключи `kind: file` в env** — многокилобайтный PEM
  в окружении каждого дочернего процесса упирается в ARG_MAX. Нужен путь к файлу
  на время команды — `sec run --file`; нужно именно содержимое в переменной —
  явный `--only <KEY>` или `--include-files`.
- **`--file` перекрывает одноимённый env-ключ**: если в пачке есть `KEY` и в том
  же запуске указан `--file KEY=...`, в окружение уйдёт путь к файлу, а не
  значение из стора (CLI предупредит в stderr).
- **`scan` и `redact` игнорируют значения короче 8 символов** (иначе совпадало бы
  в каждом втором файле). Счётчик пропущенных — в stderr, порог — `--min N`.
  Оба видят только значения из стора: это не универсальный DLP.
- **`import` строкой (`sec import proj '{"KEY":"…"}'`) светит значение в argv и
  истории shell.** Агенту — только пайп, файл или `--clipboard`.
- **Значение по `link`/`extend` read-only в потомке**: `set`/`gen`/`undo`/`import`
  откажутся. Менять — у родителя, оторвать — `sec unlink`, перекрыть своим —
  `sec set --override`.
- **`export` пишет только в файл**, в stdout — принципиально нет.
- **`sec diff` сравнивает стор со стором** (два проекта или инстанса по
  отпечаткам). Сверки с `.env` на удалённом хосте нет — прод-конфиги правятся
  мимо `sec` и расходятся со стором молча.
- **`sec export --file host:/path` пересобирает файл целиком.** Если на хосте
  есть ключи, которых нет в сторе, они пропадут. Прод-конфиг так не обновлять,
  пока не сверил состав руками.
- **`forget` необратим** — чистит историю и redo, `undo` уже не вернёт. Делать
  только после того, как новое значение проверено рабочим.
- **На Linux** мастер-ключ идёт в libsecret, если он поднят; иначе файл
  `~/.config/sec/key` или `SEC_KEY`. На headless-сервере штатный путь — `SEC_KEY`.
- **`set` со скрытым вводом требует TTY** — в headless подавать значение пайпом.

## Куда смотреть, когда

| Задача | Команда |
|---|---|
| запустить с env проекта | `sec run [proj] [--only A,B] -- cmd` |
| файловый секрет на время команды | `sec run --file [ENV=]<KEY>[:путь] -- cmd` |
| собрать `.env` | `sec export [proj] --file .env` |
| сверить значение, не раскрывая | `sec get --peek` / `--fingerprint` / `sec verify` |
| мигрировать существующий `.env`/JSON | `sec import [proj] <path\|->` |
| 2FA-код (печатать в чат безопасно) | `sec otp <proj>/<KEY>` |
| передать секрет человеку | `sec share <proj>/<KEY>` (URL печатать можно) |
| что пора ротировать / здоровье стора | `sec stale`, `sec doctor` |
| кто трогал секреты | `sec log [proj[/KEY]]` |

# sec-share — сервер одноразовых ссылок

Приёмная сторона `sec share`: хранит **только шифроблобы** (AES-256-GCM,
шифрует CLI локально) и отдаёт страницу раскрытия. Ключ расшифровки живёт во
фрагменте URL и на сервер не попадает — прочитать секреты не может даже админ.
Zero deps: один Go-бинарь на stdlib, данные — файлы в каталоге.

## Семантика

- Ссылка по умолчанию **одноразовая**: первый `POST /claim` атомарно забирает
  секрет (rename на диске — гонки и второй контейнер при деплое проигрывают),
  повторное открытие — 404.
- `--multi` — многоразовая до истечения TTL (1h…168h, кап на сервере).
- `GET /s/<id>` всегда отдаёт статичную страницу, не заглядывая в стор:
  существование ссылки не раскрывается, превью-боты ничего не сжигают.
- Reaper удаляет протухшее раз в `SEC_SHARE_REAP_EVERY`.
- Квота: не больше 100 активных ссылок на токен (утёкший токен не зальёт диск);
  claim прикрыт rate-limit по IP (берётся последний адрес `X-Forwarded-For` —
  тот, что дописал ближайший прокси).
- Контейнер работает не под root (uid 10001) — бинд-маунт `data/` должен
  принадлежать этому uid, deploy.sh делает chown сам.
- Потеря data-dir = все активные ссылки умирают; утечки нет (шифротексты без
  ключей бесполезны), поэтому data-dir сознательно не бэкапится.

## API

| Метод/путь | Auth | Что делает |
|---|---|---|
| `POST /api/v1/secrets` | Bearer | создать: `{blob, ttl(сек), once}` → `{id, expiresAt}` |
| `POST /api/v1/secrets/{id}/claim` | — | забрать: `{blob, once}`; 404 — нет/забран/протух (не различается) |
| `GET /api/v1/secrets` | Bearer | свои активные ссылки (метаданные, без блобов) |
| `DELETE /api/v1/secrets/{id}` | Bearer | отозвать свою ссылку |
| `GET /s/{id}` | — | страница раскрытия (WebCrypto, клик обязателен) |
| `GET /healthz` | — | здоровье |

## Запуск

```sh
go build -o sec-share . && SEC_SHARE_DATA=./data ./sec-share serve
./sec-share token add kai        # токен создателя: печатается один раз, хранится хэш
```

Окружение: `SEC_SHARE_ADDR` (умолч. `:8080`), `SEC_SHARE_DATA` (`/data`),
`SEC_SHARE_MAX_BLOB` (8 МиБ), `SEC_SHARE_MAX_TTL` (`168h`),
`SEC_SHARE_REAP_EVERY` (`1m`).

## Деплой (my-vpn, share.kaidstor.ru)

```sh
./deploy.sh          # DNS (Timeweb) → сборка образа → rsync → docker compose up
./deploy.sh --logs   # + логи контейнера после деплоя
```

Образ собирается локально и едет архивом (исходников на сервере нет), роутинг —
traefik по docker-labels в `compose.yml`. Секретного `.env` у сервиса нет:
токены создателей живут в `data/tokens.json` (только SHA-256-хэши) и
выпускаются на месте:

```sh
ssh my-vpn docker exec sec-share sec-share token add <имя>
sec share setup https://share.kaidstor.ru   # локально, токен — скрытым вводом
```
